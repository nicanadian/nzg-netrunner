# Example-game evaluation

Open http://localhost:5173/eval/reference.html while `npm run dev` is running. The comparison slider switches between matched screenshots of the archived and current frontend. “Inspect this position” opens the actual frontend with a read-only recording; hover, card inspection, pile inspection, legal-choice browsing, rules and game log remain available. “Play live” returns to normal AI play.

## Reference and scope

Source: [NSG’s example game](https://www.youtube.com/watch?v=xtI0-j0utLo), published June 8, 2026. The source video and its authored transcript were reviewed in Chrome. The full transcript is not redistributed here. Relevant timestamps are attached to each checkpoint.

The engine currently implements System Gateway. This evaluation preserves the teaching sequence and actual mechanics across three paired turns, using explicit Gateway substitutions. It does not reproduce every card, identity, credit total or the video’s HQ damage. See `reference-game.json` → `adaptations` for the complete differences. Its 40-card decks retain legal card counts and use the existing legal presets with order fixed only in scripted evaluation mode.

Official layout references:

- https://nullsignal.games/players/learn-to-play/learn-to-play-corp/
- https://nullsignal.games/players/learn-to-play/learn-to-play-runner/
- https://nullsignal.games/players/learn-to-play/run-guide/
- https://nullsignal.games/blog/new-learn-to-play-resources/

The Corp identity represents HQ. Roots sit at the Corp edge; ice extends toward the Runner, with outermost ice encountered first. The digital version keeps text upright, an anchored hand, compact rig groups and a separate action rail. Runner card positions are flexible under the rules. Gwent informs card emphasis and immediate feedback, not a claim of equivalent production quality.

## Reproduce the engine evaluation

```sh
npm run eval:build
npm run test:reference
```

`build-reference-eval.cjs` uses real legal decisions to generate 13 checkpoints from 66 decisions / 215 engine actions. `tests/reference-eval.cjs` regenerates the file, independently replays its trace, checks privacy and timing, and asserts actual payments, strength changes, breaks, scoring, trashing and tag removal. It also verifies normal AI/shuffle behavior is isolated from scripted mode.

`reference-viewer.js` feeds the same recorded public DTO to both frontends. It never starts a worker, saves a session, or advances the recording through game actions. The baseline is the archived frontend from before this iteration; only the identical reference-loader/guard was added. It intentionally retains the old artwork and layout.

## Reproduce the Chrome presentation evaluation

Use the already-connected Chrome extension through the trusted bundled browser client and Node REPL. Do not use native input, Firefox, T3 preview, standalone Playwright, engine globals or DOM injection. After initializing the documented browser client, call the exported function with the existing `browser` handle:

```js
var fs = await import('node:fs/promises');
var evaluator = await import('/Users/nicanadian/repos/netrunner-game/scripts/run-reference-browser-eval.mjs');
nodeRepl.write(await evaluator.runReferenceEval({
  browser, fs, root: '/Users/nicanadian/repos/netrunner-game'
}));
```

The runner creates one agent-owned tab and renders four identical checkpoints before/after at 1280×800 and 1440×900. The viewport capability applies to the selected tab, so do not interact with other tabs during the run. It records actual measured CSS viewport and DPR, loaded images, roots/ice positions, true ice order, HQ identity, clipped cards, internal board scroll, hand bounds and hidden-card data. It resets the viewport and closes its tab in `finally`.

Chrome can expose the new DOM before the compositor presents it; a short 250ms presentation wait follows DOM/image readiness before each screenshot. Inspect the resulting images, not only the metrics, to reject stale captures. `tests/reference-presentation.cjs` validates the saved measurements; it does not itself launch a browser. Browser JSON and screenshots are regenerated by the runner, never hand-edited.

## Acceptance and limits

For the selected positions at both desktop sizes, require correct root/ice geometry and order, HQ identity inside HQ, no board cards outside their mat, no additional board scrolling, fully visible hand, all card images loaded and zero hidden-card image/number leaks. Broken subroutines must remain visible during movement. These checks are concrete acceptance criteria, not an aesthetic score.

The visual hill climb corrected layout, then detected and fixed cropped outer ice, enlarged installed Runner cards, reduced empty-zone waste, added native names and preserved readable encounter results. Dense later boards still scroll internally. A separate 390×844 check verifies the scrolling mobile layout and report controls; it is not part of the 16 desktop comparisons.

Source image provenance and display conversion are recorded in `assets/card-sources.json`, `assets/cards-display/manifest.json`, `assets/cards-display/pnp-manifest.json`, `scripts/build-card-display.py` and `scripts/build-card-pnp.py`. The table uses responsive 300/600px WebP; hover/pinned inspection uses genuine 743×1029 native crops from the official 300ppi PnP PDF. The preview retains native aspect ratio. At DPR2 the 330–340 CSS-pixel inspection is fully sampled; DPR3 uses a minimum readable preview size plus selectable native rules text and can resample the image. Display images use authentic card artwork with printed credits. No sharpening or synthetic upscaling is used.
