# Expanded guide usefulness suite · 19 November 2026

Six fresh AI reviewers perform distinct guide-led tasks in two waves. They must record first impressions before reading earlier panel findings. This reduces direct suggestion bias but does not simulate genuine human novices; all reviewers use the same model family. Actual rendered controls are required. Public game DTOs may inform strategy, and full sessions are captured only at completion for replay validation. No headless Chrome, worker choices, engine-action injection, private-card strategy inputs or user-profile writes.

The planned suite includes beginner Runner learning, Corp construction constraints, stealth dependencies, keyboard/mobile navigation, custom-deck return/resume, and cross-pool interpretation. Each task records a concrete goal, observed actions/results, guide-provided help versus knowledge supplied by the tester, completion status, blocker severity, evidence and one falsifiable improvement proposal. Three reviewers complete natural custom-deck games; other reviewers prioritize broader task coverage rather than more heuristic game outcomes.

Reviewers use owned incognito tabs and unique deck names. The parent captures storage before testing and restores it after both waves. Concurrent writes to shared test storage are a limitation; each game config is checked for its exact intended documents. Reviewers must not clear storage or change global game preferences.

The review is of guide usefulness, not deck balance. Suggestions to modify a deck must specify a learning hypothesis, legality and an opportunity cost. UI task completion and deck quality are separate. Benchmark records must not be transferred to custom lists. Scores are subjective AI critique; agreement across reviewers is an occurrence count, not statistical prevalence among human players.

Planned task families:

1. Find an approachable Vantage pairing after Gateway.
2. Turn a learning goal into a small legal Runner edit.
3. Save/reopen/select that custom deck and use it in a game.
4. Choose an opponent from the Corp perspective.
5. Intentionally encounter then repair a Corp agenda/influence restriction.
6. Tune and play a Corp list for a stated learning goal.
7. Diagnose a stealth/breaker dependency rather than treating influence legality as sufficient.
8. Explain opportunity costs of a tuning hypothesis.
9. Pilot the revised stealth list through a full game.
10. Navigate the guide on a narrow viewport and with keyboard controls.
11. Distinguish preliminary six-game results, expanded results and custom-list unknowns.
12. Recover the intended pool/side/list after following guide navigation.
13. Find and edit an existing custom list in a later session.
14. Resume a game versus start a new game with changed deck choices.
15. Check whether editing preserves the saved game's original deck snapshot.
16. Choose across all three pools and explain availability boundaries.
17. Find help for influence, minimum size, copies and agenda totals.
18. Form a concrete evaluation plan for a custom revision without overinterpreting one result.

Each reviewer may add observed tasks/findings, but must retain the original task result rather than silently substituting a simpler task. Product code remains unchanged during evidence gathering.
