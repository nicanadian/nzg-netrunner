# Runner tester: guide-led deck experiment

AI reviewer using a Gateway-graduate perspective; one actual shared-browser game, not a human user study. Routine choices used a bounded DOM-click heuristic, so the strategic loss is confounded by its decisions. No screenshot-based visual audit was performed.

The guide led me to **Loup Tailored economy vs Jinteki Ambushes**, advertised as28/54 Runner wins. I used the deckbuilder to replace one Underdome Irregulars with a second Tungsten Tailor. The saved deck was40cards,7/15influence, and ready to play. The extra unique hardware is a deliberate consistency-versus-duplicate-risk experiment, not a certified improvement.

The full game ended **Corp7–Runner0 in round9**, version547 with89native choices and no diagnostics. Tailor was installed and visibly weakened ice; Tithe reached0strength. My driver ran HQ before a complete rig and took Diviner/Tithe damage, so this is not evidence that the matchup advice is wrong.

The strongest success is a specific next learning goal coupled with understandable outcome direction and sample counts. The deckbuilder made legal changes and Save & use clear. The biggest gap is that the guide gives almost no help deciding what to cut/add or how to execute the learning goal in an actual opening.

Priority improvements:

1. Add one small cut/add recipe per learning path, including legality, dependencies, duplicate risk and expected tradeoff.
2. Add mulligan priorities and a first-few-turn checklist. Separate getting an engine online from safely running it.
3. Offer Use this pairing rather than requiring exact-name copying into two lobby dropdowns.
4. Let Corp players explore from their own perspective.
5. Correct card inspector provenance: Tungsten Tailor currently says System Gateway #3 although it is a Vantage card.
